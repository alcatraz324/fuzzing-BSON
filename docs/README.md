# Фаззинг-тестирование Newtonsoft.Json.Bson

## Требования к окружению
- ОС: Kali Linux x86_64 (или совместимый Debian/Ubuntu)
- Базовые утилиты: bash, coreutils, wget, unzip
- Свободное место на диске: не менее 5 ГБ

## Быстрый старт
1. Очистить предыдущие результаты и артефакты:
   ```bash
   ./clean.sh
   ```
2. Запустить полный цикл фаззинга (установка, сборка, фаззинг, анализ):
   ```bash
   ./run_all.sh
   ```

## Режимы фаззинга
В проекте реализовано три режима фаззинга для покрытия разных сценариев:
1. **reader** — фаззинг парсера BSON (`BsonDataReader`). Проверяет устойчивость к невалидным и вредоносным входным данным при десериализации.
2. **writer** — фаззинг сериализатора (`BsonDataWriter`). Проверяет корректность и устойчивость процесса преобразования .NET объектов в бинарный формат BSON.
3. **differential** — дифференциальный фаззинг. Сравнивает результаты сериализации и десериализации, выявляя логические ошибки и несоответствия (round-trip testing).

## Структура результатов
Все результаты сохраняются в директорию `results/[RUN_ID]/`:
- `reader/` — краши и находки для режима reader.
- `writer/` — краши и находки для режима writer.
- `differential/` — краши и находки для дифференциального режима.
- `crash_analysis_report/` — итоговый отчет с анализом найденных крашей.
- `latest.txt` — содержит ID последнего запуска для быстрого доступа.

## Ручное воспроизведение крашей
Для воспроизведения найденного краша используйте собранный harness:
```bash
# Пример воспроизведения краша для reader
./build/Harness.Reader <путь_к_файлу_краша>
```
